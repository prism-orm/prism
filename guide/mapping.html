Mapping entities ​

The mapping tells Prism how a class is stored. It is written with PHP attributes on the class and its properties, and Prism deduces everything it can from the PHP types. The examples write the attributes with the Prism\ alias:

php
use Prism\Orm\Mapping as Prism;

Entities and tables ​

php
#[Prism\Entity(repositoryClass: WarehouseRepository::class)]
#[Prism\Table(name: 'warehouses')]
final class Warehouse
{
    #[Prism\Id, Prism\GeneratedValue]
    public ?int $id = null;

    #[Prism\Column(length: 80)]
    public string $name;
}

/** @extends EntityRepository<Warehouse> */
final class WarehouseRepository extends EntityRepository
{
}

#[Prism\Entity] makes a class an entity. Its options:

OptionDefaultEffect
repositoryClassEntityRepositoryThe class returned by $em->getRepository(Warehouse::class)
trackingPolicyTrackingPolicy::ImplicitHow changes are detected: see change tracking
readOnlyfalseThe entity is never compared at flush: it can be inserted and deleted, never updated

Without #[Prism\Table], the table is named after the class in snake case: Warehouse → warehouse, OrderLine → order_line. Columns follow the same rule: $createdAt → created_at. #[Prism\Table] also accepts options for MySQL and MariaDB: engine, charset, collation and comment.

The entity classes can be final, their properties public, private or readonly. Prism never calls the constructor when it loads an entity: it creates the object without it and writes the properties, so a constructor is free to require arguments.

Identifiers ​

Every entity has exactly one identifier, marked #[Prism\Id]. Composite keys are not supported.

php
#[Prism\Entity]
final class Shipment
{
    #[Prism\Id, Prism\GeneratedValue(Prism\GenerationStrategy::UuidV7)]
    #[Prism\Column(type: 'uuid')]
    public ?string $id = null;
}

#[Prism\GeneratedValue] chooses who generates it:

StrategyColumnGenerated by
Auto (default)integerIdentity under MySQL, MariaDB and SQLite, Sequence under PostgreSQL
IdentityintegerThe database, with an auto-increment column
SequenceintegerA database sequence, named <table>_id_seq unless sequenceName says otherwise
UuidV7uuidPrism, before the INSERT: time-ordered UUIDs that index well

Without #[Prism\GeneratedValue], your code assigns the identifier before persist().

Columns and types ​

Every property with #[Prism\Column] is stored. A property without a mapping attribute is never read nor written by Prism.

Prism deduces the type and the nullability from the PHP type:

PHP typeColumn typeNotes
stringstringVARCHAR(255) unless length says otherwise
intinteger
boolboolean
floatfloat
\DateTimeImmutabledatetime_immutable
arrayjson
a backed enumstring or integerthe type of the enum's values
?string, ?int…nullable

Set type for the other types: text, bigint, smallint, decimal, date_immutable, time_immutable, uuid and binary.

php
enum WarehouseKind: string
{
    case Own = 'own';
    case Partner = 'partner';
}

#[Prism\Entity]
final class Depot
{
    #[Prism\Id, Prism\GeneratedValue]
    public ?int $id = null;

    #[Prism\Column(length: 20, unique: true)]
    public string $code;

    #[Prism\Column(type: 'text')]
    public ?string $notes = null;

    #[Prism\Column]
    public WarehouseKind $kind = WarehouseKind::Own;

    #[Prism\Column(type: 'decimal', precision: 12, scale: 2)]
    public string $insuredValue = '0.00';

    #[Prism\Column(type: 'date_immutable')]
    public ?\DateTimeImmutable $openedOn = null;

    #[Prism\Column]
    public array $openingHours = [];
}

The rules that keep data exact:

  • A decimal is always a PHP string: an amount is never rounded by a float. precision and scale are required.
  • Dates are \DateTimeImmutable. A \DateTime property is refused when the mapping is validated.
  • The nullability comes from the PHP type. #[Prism\Column(nullable: false)] on a ?string is a contradiction, and an error.

The other options of #[Prism\Column]:

OptionEffect
nameThe column name, instead of the property name in snake case
lengthThe length of a string or binary column
fixedA fixed-length column: CHAR or BINARY instead of VARCHAR or VARBINARY
uniqueA unique constraint on this column alone
defaultThe default value of the column in the database
enumTypeThe backed enum of the property, when it cannot be read from the PHP type
insertable, updatablefalse leaves the column out of INSERT or UPDATE statements: for columns computed by the database
sensitiveThe value is masked in the audit log

Custom types extend Prism\Dbal\Type\Type and are registered in the TypeRegistry of the connection; in Symfony, a service tagged prism.type is registered for you.

Embeddables ​

An embeddable is a value object stored in the columns of the entity that contains it:

php
#[Prism\Embeddable]
final class PostalAddress
{
    #[Prism\Column(length: 120)]
    public string $street;

    #[Prism\Column(length: 10)]
    public string $postcode;

    #[Prism\Column(length: 80)]
    public string $city;
}

#[Prism\Entity]
final class Supplier
{
    #[Prism\Id, Prism\GeneratedValue]
    public ?int $id = null;

    #[Prism\Embedded]
    public PostalAddress $address;

    #[Prism\Embedded]
    public ?PostalAddress $billingAddress = null;
}

The columns are prefixed with the property name: address_street, billing_address_city. columnPrefix sets another prefix, or none with false.

A nullable embeddable is null when all its columns are NULL. Its columns are nullable in the database, whatever their PHP types say.

Indexes and unique constraints ​

php
#[Prism\Entity]
#[Prism\Index(fields: ['lastName', 'firstName'])]
#[Prism\UniqueConstraint(fields: ['email'])]
final class Contact
{
    #[Prism\Id, Prism\GeneratedValue]
    public ?int $id = null;

    #[Prism\Column(length: 80)]
    public string $firstName;

    #[Prism\Column(length: 80)]
    public string $lastName;

    #[Prism\Column(length: 180)]
    public string $email;
}

fields lists PHP properties, not columns; address.city designates a field of an embeddable. The index names are generated from a hash of their columns, so they stay the same from one schema diff to the next; name sets one yourself.

Optimistic locking ​

php
#[Prism\Entity]
final class StockLevel
{
    #[Prism\Id, Prism\GeneratedValue]
    public ?int $id = null;

    #[Prism\Column]
    public int $quantity = 0;

    #[Prism\Version, Prism\Column]
    public int $version = 1;
}

With a #[Prism\Version] field, each UPDATE checks that the row still has the version that was loaded, and increments it. If another process changed the row in between, no row matches and the flush throws OptimisticLockException, which names the entity and the expected version. The version can also be a \DateTimeImmutable.

Lifecycle callbacks ​

A method of the entity can run at each step of its life:

php
#[Prism\Entity]
#[Prism\HasLifecycleCallbacks]
final class Quote
{
    #[Prism\Id, Prism\GeneratedValue]
    public ?int $id = null;

    #[Prism\Column(length: 20)]
    public string $reference = '';

    public string $label = '';

    #[Prism\PrePersist]
    public function assignReference(): void
    {
        $this->reference = 'Q-' . bin2hex(random_bytes(4));
    }

    #[Prism\PostLoad]
    public function computeLabel(): void
    {
        $this->label = 'Quote ' . $this->reference;
    }
}

The callbacks are PrePersist, PostPersist, PreUpdate, PostUpdate, PreRemove, PostRemove and PostLoad. Since the constructor is not called when an entity is loaded, #[Prism\PostLoad] is where derived state is computed. A change made in PreUpdate is included in the UPDATE.

To keep this code out of the entity, move it to listener classes declared with #[Prism\EntityListeners([QuoteListener::class])]: their methods carry the same attributes and receive the entity as first argument.

Validating the mapping ​

The mapping is checked when an entity is first used, and all at once by:

console
$ bin/console db:schema:validate
console
$ vendor/bin/prism db:schema:validate

Each error names the class and the field, and says how to fix it. The command also compares the mapping with the database and lists the differences.
