Prism ORMThe PHP ORM for business applications

N+1 queries prevented by default, queries checked by PHPStan, multi-tenancy that fails closed. Built on PHP 8.4.

Why Prism?
GitHub
⚡

No more N+1 queries

Lazy relations load in batches. Looping over 100 orders and their customer costs 2 queries, not 101, without a single join written by hand.

🛡️

Typed queries, checked by PHPStan

A generated metamodel replaces field-name strings. A typo or a value of the wrong type is an error in your IDE, not in production.

🏢

Multi-tenancy and audit, built in

Every query is filtered by the current tenant and raw SQL is checked. No tenant, no query. Changes are audited in the same transaction.

🔎

Vector and hybrid search

Store embeddings next to your data. nearest() and hybridSearch() search by meaning and by words, after the tenant filter, and stale vectors are recomputed after the commit.

Loop over relations without thinking about it ​

Every entity loaded by one query belongs to a cohort. When you touch a lazy relation of one of them, Prism loads the same relation for the whole cohort in one IN (...) query.

php
$orders = $em->getRepository(Order::class)->findAll();

foreach ($orders as $order) {
    echo $order->customer->name, "\n"; // every customer is loaded with the first one
}

Queries without strings ​

php
$o = Order_::as('o');

$orders = $em->query($o)
    ->where($o->status->eq('open'))
    ->orderBy($o->placedAt->desc())
    ->limit(20)
    ->getResult(); // list<Order>

Order_ is generated from your entity. Rename a field and every query that uses it stops compiling in PHPStan.

One database, many customers ​

php
// the current tenant is Acme: only Acme's invoices, here and in every lazy load
$invoices = $em->getRepository(Invoice::class)->findAll();

// every tenant at once: only explicitly
$count = $tenants->runAsSystem(fn () => $em->getRepository(Invoice::class)->count());

Without a current tenant, a query on a tenanted entity throws. There is no implicit "all tenants" mode.
